## 2. 核心 Skills 资产库全景

### 2.1 视觉与画面连续性 Skills
- **`authentic-scene-background` (真实实景底图纪律与生图流水线)**
  - 彻底杜绝纯色背景板（如灰白 `(248, 250, 252)` 或纯黑死底）。
  - 强制要求采用**实际高清大图 / 真实高精度场景照片**（东京实拍实景、教室日常、3D 工程装配体、工厂现场），并叠加 58% 偏右构图与多级暗色渐变暗角（Vignette），确保左侧教学 HUD 卡片极高可读性。
  - **生图级联策略 (Google Image -> fal.ai Fallback)**：优先调用 Google Image 生成高清真实场景底图；当免费/配额 usage 用尽或请求受限时，自动无缝切换至 `fal.ai` (`fal-ai/recraft-v3`, `fal-ai/flux`, `fal-ai/ideogram/v2`) 继续生成 8K 级高清大图，保证流水线 100% 不断流。
- **`character-continuity` & `ai-environment-continuity` (角色与场景一致性)**
  - 锁定面部特征、服饰与光影种子，在多镜头切换中保持主人公/环境的一致性。
- **`stickman-explainer` (火柴人极简抽象原理解说)**
  - 专门处理无实景素材的抽象逻辑概念，以极简线条动画降低认知负荷。
- **`ypp-thumbnail-design` (超高点击率封面工程与烧录纪律)**
  - 执行 3 色架构法则与高对比度强化；
  - 右下角严格预留 20% 时长角标避让安全区；
  - 每一期采用全新独立底图 Hash，坚决杜绝历史封面复用被算法降权；
  - **首帧封面硬编码烧录时长规范**：短片（9:16 Shorts）封面硬编码烧录显示 **整整 1.0 秒**（30 帧），长片（16:9 Long-Form）主封面硬编码烧录显示 **整整 1.5 秒**（45 帧），彻底杜绝移动端抓取残帧或播放器首帧闪黑。

### 2.2 声音与配音工程 Skills
- **`voice-separation-discipline` (严苛语音分离纪律)**
  - 解决 TTS 跨语言吞音与发音畸变：解说员（中文 `Yunxi` / 英文 `Andrew`）绝对严禁朗读目标外语单词、假名或罗马字；
  - 目标语言由母语 Native TTS（如东京标音 `Nanami`）独立播报，双音轨精准交织。
- **`human-like-voice-synthesis` (拟人化语音自然韵律)**
  - 注入语速微调、思考气口与段落间隙，彻底消除机械 AI 朗读感。
- **`music-scoring` & `voice-band-carve` (动态音频闪避与避让滤波)**
  - 在旁白出现频段（1kHz - 3.5kHz）对背景音乐进行针对性衰减（EQ Ducking），避免音乐盖过人声。

### 2.3 互动教学与跟读 Skills
- **`millisecond-karaoke-follow-along` (毫秒级卡拉OK词级跟随高亮)**
  - 彻底告别静态无聊死板字幕。通过 Whisper 提取词级（Word-Level）毫秒时间戳；
  - 发光黄金胶囊（Glowing Capsule）配合红色跳动拍子点（Mora Cadence Dot），外加 80ms 视觉预判前导，观众视线自然跟随。
- **`shorts-native-audio-drill` (竖屏短视频原声跟读防冷场)**
  - 短视频 Stage 3 跟读训练阶段，严禁录入空白静音，强制播放第二次 Native 母语标准发音，观众在听觉强化中完成影子跟读。

### 2.4 质量控制与交付 Skills
- **`tokyoflow-qc-gate` (UMS 99 分全自动质检门禁)**
  - 上传前强制执行 10-12 项硬性检查：音画同步、首帧封面烧录、无死音黑帧、文字边缘防截断、字体回退保全、零 Emoji 检查等，低于 99 分阻断发布。
- **`free-study-companion-drive` (免费复习讲义与 Drive 自动同步)**
  - 自动渲染 300 DPI A4 矢量排版 PDF 讲义，自动上传至公开 Google Drive，视频片尾生成提取口令，置顶评论自动注入直链。
- **`zero-emoji-discipline` (全域 0 Emoji 严苛纪律)**
  - 彻底禁止在视频、标题、字幕、文案、封面及文档中出现任何 Emoji，保持严谨专业的视觉与文本调性。

## 3. 端到端全自动生产 Pipeline 流水线

以 Micro-Forensics、AI Classroom Copilot 与 TokyoFlow 为代表的 10 阶段全自动流水线：

```
1. 【热点/卷宗/大纲雷达扫描 (Radar)】
   └── 抓取真实公开卷宗 (WARN/NIST/SAE) 或大纲课程库，过滤虚假营销
2. 【5 维商业量化打分 (Evaluator)】
   └── 痛感度(30%) + 搜索需求(25%) + 竞品空白(20%) + 视觉可行性(15%) + 高商业 RPM(10%) -> >= 80分准入
3. 【叙事架构轮换 (Narrative Sequencer)】
   └── 按 EP_IDX % 7 轮换 7 大叙事模型，彻底杜绝 AI 式陈词滥调
4. 【剧本与双音轨合成 (Narrative & Multi-TTS Engine)】
   └── 剧本纯净化处理 -> 分语言生成纯净语音 (Edge TTS / Kokoro) -> 获取精确时长
5. 【Whisper 毫秒级字词对齐 (Word Alignment)】
   └── 提取每个单词毫秒起点与终点，生成卡拉OK逐词高亮序列
6. 【视觉母版与 HUD 卡片排版 (Slide Designer & Compositor)】
   └── 真实实景底图合成 + 磨砂卡片 + 苹方/冬青字体安全边距排版
7. 【首帧封面硬编码烧录 (First-Frame Master Cover Burn-In)】
   └── 短片（9:16 Shorts）硬编码烧录显示整整 1.0 秒（30 帧），长片（16:9 Long-Form）硬编码烧录显示整整 1.5 秒（45 帧），确保移动端 Feed 抓取完美封面且播放器预览零黑帧
8. 【FFmpeg 音画微秒合成与音频闪避 (Video Renderer)】
   └── 1080p/4K 渲染，人声频段避让滤波，无黑帧死音
9. 【自动化 UMS 99 分质检门禁 (QC Gate)】
   └── 自动扫描黑帧、音量均值、文本越界、封面烧录时长、Emoji 与违禁词，未达标自动阻断
10. 【双通道排期分发与社群置顶 (YouTube Publisher & Drive Manager)】
    └── 上传公开 Drive 讲义，多语言播放列表隔离，自动化预约定时发布
```

## 4. 起号策略与矩阵化运营

### 4.1 核心起号三阶段逻辑
1. **冷启动期（第 1-14 天）：高密度垂直内容喂饱算法**
   - 保持工作日每日 1 条长片 + 1 条 Shorts，周末发布 1 小时合集/大片；
   - 纯净垂直定位：前 10 条视频标签、分类、受众标签高度收敛，让推荐模型迅速建立观众肖像。
2. **成长期（第 15-45 天）：高时长合集攻克 4,000 小时门槛**
   - 单靠短视频无法积累 YPP 4,000 小时有效长视频播放时长；
   - 必须通过**周末 1 小时沉浸式全场景合集**（如 Tokyo Life 1-Hour Mega-Compilation 或 3D 机械剖面全集）作为拉时长引擎。
3. **破圈期（第 46-90 天）：大片级深度专题 + 免费讲义钩子锁留存**
   - 结合文化/热门事件（如电影大片深度拆解、明星原声现场、热点工厂闭厂调查）；
   - 片尾口令引导自取 Drive 讲义，置顶评论沉淀高忠诚度私域受众。

## 5. 踩坑复盘与惨痛教训 (Lessons Learned & Pitfalls)

1. **TTS 混合语言吞音与发音崩溃**
   - *教训*：直接让中文 TTS 朗读包含日文假名或英文字符的台词，会导致大面积吞音、杂音爆音或语速骤降。
   - *对策*：建立**严格语音分离纪律**。中文解说词中严禁出现任何日文字符，必须全部纯化为中文术语或交由 Native TTS 分轨朗读。
2. **短视频封面被 YouTube 随机抓取丑帧与长片预览黑屏**
   - *教训*：YouTube Shorts 官方 API 不支持上传自定义封面，默认随机截取画面，经常抓到黑屏或眨眼帧；长片播放器启动时若无首帧烧录易出现空白闪烁。
   - *对策*：执行**精确时长首帧主封面烧录纪律**。短视频（9:16 Shorts）硬编码烧录显示 **整整 1.0 秒**（30 帧），长片（16:9 Long-Form）硬编码烧录显示 **整整 1.5 秒**（45 帧），强行让算法抓取该帧作为展示封面并确保播放器预览完全展示高质母版。
3. **生图配额耗尽导致流水线崩溃中断**
   - *教训*：单纯依赖单一云端生图接口，一旦遇到 API 限流、每日配额耗尽（Quota Exhausted）或者并发超出，整条自动化脚本直接抛错中断，导致定时发布延误。
   - *对策*：实施**双层生图级联容灾机制 (Google Image -> fal.ai)**。优先使用 Google Image 产出真实高清大图；一旦检测到 usage/quota 用尽或 HTTP 429/403，无缝自动降级切换至 `fal.ai` (如 `fal-ai/recraft-v3` / `flux` / `ideogram/v2`)，同时确保尺寸与风格对齐，实现零停机自动出片。
4. **短视频跟读环节陷入尴尬死音**
   - *教训*：早期在跟读环节留出 3 秒静音供观众跟读，预录制视频下观众因没有即时麦克风反馈，死音直接导致完播率暴跌。
   - *对策*：Stage 3 **原声二次强化跟读**，直接播放 Native 发音，配以动效卡拉OK，观众听着原声同步开口，完播率显著提高。
5. **封面背景复用被算法判定低质**
   - *教训*：为了省事在不同期数使用同一张背景图或纯暗色背景，点击率骤降，且被判定为模板化量产内容。
   - *对策*：强制每期独立现场实拍图/3D 渲染图，背景图 Hash 唯一性校验，杜绝纯色背景板。
6. **字体缺少字重导致排版生硬或乱码**
   - *教训*：单一 Arial Unicode 导致字重生硬、日文标点符号或波浪线 `〜` 渲染为豆腐块乱码框 `⌧`。
   - *对策*：全面迁移至原生**苹果苹方（PingFang SC）**，并建立 `PingFang -> Hiragino Sans GB -> Arial Unicode` 三级降级保全链，文字边距动态计算杜绝截断。
7. **多语言观众信息流交叉污染**
   - *教训*：中文长片与英文长片混发且均通知订阅者，导致英文母语订阅者被中文内容刷屏而迅速退订。
   - *对策*：中文列发布时将 `notifySubscribers` 设为 `False`，同时严格隔离专属双语播放列表。

## 6. 工业级最佳实践 (Best Practices & Standard SOP)

1. **先证明故事/视觉成立，再投入重度生产（Creative Proof First）**
   - 制作前先锁定不可覆盖的脚本大纲与 90 秒开场小样，验证矛盾张力。严禁在画面和故事尚未成立前就盲目铺开多语言翻译和 4K 重度渲染。
2. **轻量本地化资产管道（PIL + Edge TTS + FFmpeg）**
   - 能用本地矢量合成与轻量 API 完成的模块，绝不盲目依赖重度云端慢速渲染服务；
   - 保持单条命令、单一 Spec 文件生成完整 Candidate 候选片。
3. **坚持 0 Emoji 与专业视觉克制**
   - 弃用廉价网络表情符号，改用专业的文本胶囊标签（如 `[JLPT N5]`、`【案发第 01 号】`、`SAE J300`），塑造高可信度专家媒体形象。
4. **全自动质检（QC Gate）是最后一道安全阀**
   - 绝不凭肉眼侥幸。黑屏阈值、音量均值、字幕边缘防截断必须全部写入自动化测试，达到 99 分以上才触发上线发布。
